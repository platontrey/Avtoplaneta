# Vehicle catalog

`vehicles.json` — справочник марок, моделей, кузовов и двигателей автомобилей. Это единственный
источник выпадающих списков «Бренд», «Модель», «Марка кузова» и «Марка двигателя»: и веб, и мобильное приложение
получают его одним ответом `GET /api/vehicle-catalog`, поэтому этих списков
не должно быть ни в TypeScript, ни в Dart.

## Чем отличается от catalog.json

| | `catalog/catalog.json` | `vehicles/vehicles.json` |
|---|---|---|
| Кто меняет | человек | команда `make vehicle-catalog` |
| Что описывает | поля форм и шаблоны дефектовки | марки, модели, кузова и двигатели |
| Версия | ставится руками | дата + отпечаток содержимого |

Справочники разделены сознательно: у них разный жизненный цикл, и обновление
марок не должно сбрасывать клиентский кэш каталога запчастей (678 КБ) — у
каждого свой ETag.

## Как обновить

```sh
cd backend && make vehicle-catalog
```

Команда обходит `https://www.drom.ru/catalog/`, страницы марок, подразделы кузовов (`/frame/`)
и двигателей (`/engine/`), перезаписывает этот файл и прогоняет тесты справочника.
Прогон выполняется параллельным пулом потоков и занимает около минуты.

Версия считается как дата плюс отпечаток содержимого, поэтому повторный запуск
без изменений на сайте не меняет ни версию, ни ETag, и клиенты ничего не
перекачивают. Дифф файла перед коммитом стоит просмотреть: заметное падение
числа записей означает, что на сайте поменялась разметка.

## Формат

```json
{
  "version": "2026-10-01.ab12cd34",
  "source": "https://www.drom.ru/catalog/",
  "generated_at": "2026-10-01T14:00:00Z",
  "brands": [
    {
      "name": "Toyota",
      "slug": "toyota",
      "bodies": [ "ACV40", "NZE121" ],
      "engines": [ "1NZ-FE", "2AZ-FE" ],
      "models": [
        {
          "name": "Camry",
          "slug": "camry",
          "bodies": [ "ACV40", "XV50" ],
          "engines": [ "2AZ-FE", "2AR-FE" ]
        }
      ]
    }
  ]
}
```

Марки, модели, кузова и двигатели отсортированы по имени без учёта регистра — это проверяется в
`validateVehicleCatalog`, чтобы порядок не «плавал» между прогонами и дифф
оставался читаемым.

Поле `slug` нужно парсеру для сопоставления записей между запусками; клиенты
показывают `name`, `bodies` и `engines`. Значения, которых нет в справочнике,
вводятся руками — списки подсказывают, но не ограничивают, иначе
редкие машины и спецтехнику стало бы невозможно завести.
