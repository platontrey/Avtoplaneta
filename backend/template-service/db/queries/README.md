# Стандарты организации SQL-запросов (Domain-Driven SQL)

Каждый сервис проекта Avtoplaneta организует SQL-запросы в директории `db/queries/` по строгим архитектурным правилам:

1. **Запрет на монолитный `queries.sql`:**
   - Запросы разделяются по субдоменам и сущностям:
     - `<entity>_crud.sql` — базовые CRUD операции (Create, Read by ID, Update, Delete).
     - `<entity>_stock.sql` / `<entity>_lifecycle.sql` — специфические транзакционные операции домена.
     - `<entity>_stats.sql` — аналитические отчеты и агрегации.
     - `outbox.sql` — события Transactional Outbox.
2. **CTE (`WITH ... AS`) вместо вложенных подзапросов:**
   - Запрещено использовать вложенные конструкции `FROM (SELECT ...) sub` или `LEFT JOIN (SELECT ...)`.
   - Любая предварительная фильтрация, склейка идентификаторов или агрегация оформляется в именованные CTE, читающиеся сверху вниз.
3. **Строгая типизация параметров sqlc:**
   - Использовать явные аннотации типов `sqlc.arg(name)::type` или `sqlc.narg(name)::type`.
